# 不依赖 Render 的实现路线

## 当前推荐路线

- 前端生成视频
- Supabase 保存作品和分享链接
- Vercel 承载页面、历史记录和分享页
- Render / 其他后端渲染服务只作为可选增强项，不再是必须依赖

## 为什么这样更适合当前项目

- 你希望先做成一个自己真的能用的回忆录工具
- 但又不想被绑卡、部署后端服务卡住
- 当前浏览器端已经具备生成能力，桌面端体验稳定
- 手机端重点是：
  - 直接上传相册素材
  - 生成结果后保存到云端
  - 生成分享链接

## 当前产品定位

- 系统浏览器中的 Safari / Chrome：优先支持本地生成
- 微信内置浏览器：不保证稳定生成，建议跳转系统浏览器
- 桌面端：生成体验最佳

## 当前用户路径

1. 手机或电脑导入照片
2. 在浏览器端生成视频
3. 保存到 Supabase
4. 生成公开分享页
5. 在任何设备上查看结果

## 后续再做服务端渲染时

- 只需要补一个独立渲染服务
- 然后给前端配置：

```bash
VITE_RENDER_API_BASE_URL=https://你的渲染服务域名
```

- 不需要推翻当前前端和 Supabase 的方案
